# ReadX v2 Design

> Status: historical approved design spec. Implemented and released as v2.0.0; v2.1 is docs-only cleanup.

## Goal

v2 makes ReadX useful as a daily desktop utility. It adds persistence, history, manual import, configurable hotkeys, better replay controls, text cleanup, and classic ORP RSVP output while keeping the app compact.

## Release Shape

v2 was delivered as one large release from the `v2` branch. It was built foundation-first: persistence and data contracts first, shared text/playback pipeline next, then ORP rendering, hotkey customization, and the left-tab UI.

The main window uses left-side tab navigation:

- `Capture`
- `Import`
- `History`
- `Settings`

The UI should remain a compact Windows utility rather than a large dashboard. The left navigation avoids a tall portrait layout while leaving enough horizontal room for history and settings.

## Scope

### In Scope

- JSON settings persistence in the user's app data location.
- Raw-text history with timestamps, source type, and stable ids.
- Configurable history limit with default `20`.
- Duplicate history entries are kept.
- Quick manual import: paste text, play it, and add the raw text to history.
- Configurable hotkeys for capture, replay last, pause/resume, and cancel.
- Replay controls: pause/resume, restart from beginning, and cancel.
- Automatic text cleanup enabled by default, with a global on/off setting.
- Classic ORP RSVP rendering with fixed v2 visual design.
- Left-side tab UI for Capture, Import, History, and Settings.

### Out Of Scope

- Full visual identity redesign.
- Overlay customization controls.
- Shortcut manager for every app action.
- Manual history deletion or clear-history actions.
- Named reading presets.
- Import library with titles or external file sources.
- Scrubbing, skip forward/back, live playback position, or detailed progress navigation.
- Advanced OCR preprocessing unless needed to keep existing v1 behavior working.

## Settings

ReadX stores settings as human-readable JSON in the user's app data location, not in the repo or install directory. If the settings file is missing or invalid, the app uses defaults and remains usable.

Settings include:

- Default WPM.
- Cleanup enabled flag.
- History limit, default `20`.
- Capture hotkey.
- Replay-last hotkey.
- Pause/resume hotkey.
- Cancel hotkey.
- Window width, height, left, top, and maximized state.

Settings save automatically after user changes. Hotkey changes attempt to re-register immediately.

## History

History is an activity log, not a library.

Each item stores:

- Stable id.
- Created timestamp.
- Source type: `Capture` or `Import`.
- Raw text.

History does not store cleaned text, tokens, ORP positions, WPM, old playback position, or capture region. Replay always runs the raw text through the current cleanup, tokenization, and RSVP rendering pipeline.

When a new item pushes history beyond the configured limit, the oldest item is removed. Lowering the history limit trims oldest entries after the setting is saved. Empty text is never added to history.

Replaying a history item does not create another history entry.

## Text Pipeline

Capture, import, and history replay share one text pipeline:

```text
raw text -> optional cleanup -> word splitting -> RSVP session -> ORP playback
```

Cleanup is enabled by default and can be disabled globally. Cleanup should cover the practical v2 cases:

- Collapse repeated whitespace.
- Trim empty leading/trailing content.
- Join line wraps that are likely wrapping one paragraph.
- Rejoin hyphenated line-wrap fragments.
- Remove obvious OCR junk only when the rule is conservative.

If cleanup or tokenization produces no playable words, ReadX should show a status message and not start playback.

## Playback

Playback builds on the existing `RsvpPlayer`, `RsvpSession`, `RsvpPresenter`, and `RsvpOverlay` split.

Required v2 controls:

- Pause/resume.
- Restart from the beginning of the current session.
- Cancel playback and close the overlay.

These controls must work from the UI and from configured hotkeys where relevant. Future playback navigation, scrubbers, skip controls, and live position display are deferred.

## ORP Rendering

v2 uses classic ORP focused-letter rendering.

For each word:

- Calculate the optimal recognition point letter.
- Highlight that letter with the fixed v2 focus color.
- Position the word so the ORP letter lands on a stable visual anchor.

ORP calculation should be pure logic with focused tests. Overlay customization is out of scope for v2; color, font, guide position, and spacing are fixed defaults.

## Hotkeys

The current single fixed capture hotkey expands to configurable bindings for:

- Capture.
- Replay last.
- Pause/resume.
- Cancel.

The hotkey service should support multiple registrations and report which registrations fail. If one hotkey conflicts, ReadX remains usable and shows the failed binding status instead of disabling unrelated functionality.

## UI

The main window uses left-side tab navigation with compact content.

The default Capture tab should prioritize:

- Capture action.
- Current WPM.
- Playback controls.
- Last text preview.
- A small recent-history preview or link to the History tab.
- Status for OCR and hotkeys.

The Import tab should provide:

- A multiline paste box.
- Play action.
- Clear text action for the current paste box only.

The History tab should provide:

- List of raw-text history items by timestamp, source, and preview.
- Replay action per item.
- Visible current history limit.

The Settings tab should provide:

- Default WPM.
- Cleanup toggle.
- History limit.
- Hotkey editors for capture, replay last, pause/resume, and cancel.
- Status for hotkey registration conflicts.

Workflow logic remains in `AppController` or focused services. Views should expose events and state setters rather than owning orchestration.

## Error Handling

- Missing settings file: use defaults.
- Invalid settings file: use defaults and overwrite on next save.
- Missing history file: start with empty history.
- Invalid history file: start with empty history and keep the app usable.
- OCR unavailable: capture is disabled, but import and history replay remain usable.
- Hotkey conflict: show which binding failed and keep other controls usable.
- Empty capture/import text: do not add history and show a status message.
- No playable words after cleanup/tokenization: do not play and show a status message.

## Testing

Automated tests should focus on low-risk pure logic and contracts:

- Settings defaults and invalid-file fallback.
- History retention, duplicate behavior, and replay contract.
- Cleanup on/off behavior.
- ORP letter calculation.
- Hotkey mapping and multi-registration outcomes where practical.
- Controller workflow for capture/import/history replay where dependencies can be faked.

Manual golden path must be run before v2 is declared done:

- App restart preserves settings.
- Capture adds raw text to history and plays it.
- Import adds raw text to history and plays it.
- History replay reprocesses raw text and does not add a duplicate entry.
- Cleanup toggle changes playback input behavior.
- Configured hotkeys work.
- Hotkey conflict is reported without breaking unrelated controls.
- ORP anchor remains visually stable during playback.
- Pause/resume, restart, and cancel work from supported controls.
